## DEFERRED (scope-affecting, logged per framework)
Balance-ordering of the network list and the zero-balance "All networks (N)"
collapse were NOT implemented. Reason: walletService.networkWallets is keyed by
master-wallet id and holds ONLY the active network's wallet (JSDoc: "reflects the
current globally active network"); on network switch the map is rebuilt. So
per-network fiat balances cannot be read without createNetworkWallet, which can
trigger safe init + a master-password prompt (the WO-34 hazard). Attribution of
per-network balances belongs to the read-only TotalAssetsService in WO-34 (which
constructs cache names from metadata without instantiating wallets). When WO-34
lands, revisit ordering + zero-collapse here.
